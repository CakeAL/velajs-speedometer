# 速度计

Xiaomi Vela JS GPS 速度计。用户已确认原有实时测速逻辑在真机正常工作；本次新增的页面、统计和 GPX 功能仍需真机验证。

- 测速页：大号实时速度，左右两栏历史平均与历史最高，海拔、记录时长与轨迹点数；点击单位切换 km/h、m/s、mph。
- 定位页：大字号经纬度与方向，下方并列展示海拔、水平定位精度。
- 轨迹页：浏览已完成的 GPX，选择文件查看轨迹点数、时长及海拔范围，单独确认删除。

原 `pages/detail` 示例页已删除。应用内三个页面共享同一个 GPS 会话，切页不会重新创建定位订阅。

## 记录与统计

点击「记录」创建轨迹，按钮变为「结束」。每秒将最新有效经纬度、UTC 时间和设备返回的海拔追加到文件；缺失坐标或 GPS 数据超过 5 秒未更新时跳过该秒，不补造坐标。设备未返回海拔的点省略 `<ele>`，不会将缺失海拔写成零。点击「结束」关闭 GPX XML 并保存。

文件位于手表应用私有目录 `internal://files/speedometer/`，文件名使用 UTC 时间。写入中使用 `.part`，完成后变为 `.gpx`。异常退出时，下次进入轨迹页会用分块读取尝试恢复完整轨迹点，丢弃写了一半的末尾。长轨迹的记录、浏览和恢复采用分块方式，避免把整个轨迹放进内存。

记录在应用内切换页面时继续；应用进入后台或退出时停止定位并尝试结束保存。当前没有申请后台运行能力，不承诺退出应用后继续采点；若平台中断了保存，会留下待恢复文件。

历史平均以每秒的有效速度样本计算，包含静止的零速度，排除定位中断的时间；最高值取有效 GPS 速度的峰值。统计在本地持久化，跨次打开应用累积，与 GPX 文件删除相互独立。应用卸载会清除私有文件和统计。

## 定位流程

保留参考「腕上时速」1.0.6 的取速方式：进入前台同时调用一次 `geolocation.getLocation`（60 秒超时）与持续 `geolocation.subscribe`。原始 m/s × 3.6 转换为 km/h，低于 0.5 km/h 归零，内部保留一位小数，实时显示默认整数时速。

速度、坐标、海拔独立校验。5 秒未更新时实时速度归零并显示等待更新，15 秒未更新的坐标和海拔隐藏。定位错误或超时 5 秒后自动重新订阅；权限或接口不可用时每 15 秒重试，仍需用户在设备设置允许定位权限。持续一分钟无更新也会重新连接。后台和退出取消重试与订阅，旧回调不能覆盖新数据。

## 手机导出

按本次用户决定，仅实现本地 GPX 记录与管理，手机导出方式后续确定。当前没有手机上传/导出按钮，也没有配套安卓接收应用或服务器。

官方 [interconnect](https://iot.mi.com/vela/quickapp/zh/features/network/interconnect.html) 可发送数据到配套安卓应用，要求两端包名和签名一致；[uploadtask](https://iot.mi.com/vela/quickapp/zh/features/network/uploadtask.html) 上传到开发者服务器，仅部分机型支持。

## 开发与验证

```sh
npm install
npm test
npm run build
npm run start
```

调试包：`dist/com.cakeal.speedometer.debug.1.0.0.rpk`。发布使用 `npm run release`，需要配置自己的签名。

单元测试覆盖取速、自动重试、跨页会话、持久化统计、每秒 GPX 采样、海拔缺失、异常恢复及文件读取。请在真机补充验证：三个页面跳转、短程记录、断 GPS 后恢复、结束保存、文件浏览/删除、退出后再打开。模拟器的 GPS 结果不能替代真机验证。

仅适配带 GPS 且向 Vela JS 应用开放 `system.geolocation` 的设备；设备支持以[官方明细](https://iot.mi.com/vela/quickapp/zh/features/system/geolocation.html)为准。圆屏、方屏、窄屏按形状与比例选择布局，不覆盖无 GPS 设备或其他操作系统。

## 图标

`src/common/logo.png` 是 192 × 192 的透明 PNG，符合[官方图标建议](https://iot.mi.com/vela/quickapp/zh/guide/framework/manifest.html)。由内置 imagegen 生成后缩小到交付尺寸；生成要求为：深蓝圆形底、薄荷绿速度表弧线与指针、白色刻度，无文字、无外部阴影，圆形外部透明。
