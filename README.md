# 速度计 · Speedometer

Xiaomi Vela JS GPS 速度计，配套 AstroBox 插件同步、管理和导出 GPX 轨迹。手表应用版本为 **1.0.1**，AstroBox 插件版本为 **1.0.0**，支持圆屏、方屏和窄屏布局。

可以用来没事记录一下你所乘坐的交通工具（公交车/出租车/轻轨/有轨电车/地铁（地上段））的速度，以及gpx轨迹。

## 安装

- **设备要求**：带 GPS，且向 Vela JS 应用开放定位接口的手表／手环。
- **手表端**：使用适配设备的快应用安装工具安装 `dist/com.cakeal.speedometer.debug.1.0.1.rpk`，打开速度计并允许定位权限。
- **手机端**：使用 AstroBox 2.2.0 或更新版本，在插件管理页导入 `speedometer-astrobox-plugin/dist/Speedometer GPX.abp`，启用插件并允许所需权限。

## 测速与定位

打开速度计，在室外开阔处等待顶部显示「GPS 已定位」，首页会显示实时速度、海拔、本次平均与本次最高速度。点击速度下方的单位，在 **km/h、m/s、mph** 间切换；点击「详情」查看经纬度、海拔和水平定位精度，点击「返回测速」回到首页。左右滑动可在「测速—定位详情—轨迹」之间循环切换，纵向滑动仍用于滚动当前列表。

除录制的 GPX 轨迹外，手表应用不持久保存其他使用数据。平均与最高速度每次打开应用重新统计，不保存到下次使用；未记录时退出再打开也会重置。切换页面、开始或结束 GPX 记录不会重置本次统计；熄屏、后台返回和页面切换都继续累计，只有应用真正结束后再次创建会话才清零。统计重置不会断开 GPS。平均值包含静止时的有效零速度，排除定位中断时间。字段显示 `--` 表示尚未获取到数据。

应用启动后持续订阅 GPS，并在前台保持系统屏幕常亮。「自动熄屏」采用应用内纯黑覆盖层，避免自然熄屏进入后台；小圆点沿用首页 GPS 状态颜色，点按任意位置恢复当前页面，读数和记录继续累计。测速、定位详情和轨迹页均支持。黑层显示期间只更新 GPS 指示点，点按恢复后显示最新读数。

在「详情」顶部点击屏幕模式，原有三档保持不变：「记录时常亮」在录制和保存时显示完整页面，其余时候闲置 10 秒显示黑层；「始终常亮」始终显示完整页面；「10 秒自动熄屏」在记录期间也会闲置 10 秒显示黑层。触摸页面或点按黑层会重新计时，设置仅在本次运行有效。黑层并未关闭屏幕，持续定位和常亮仍会耗电。按实体按键真正熄屏、切到其他应用或系统结束应用，仍受设备实际后台能力限制。

## 记录与查看轨迹

1. 首页点击「记录」，按钮变为「结束」，开始每秒保存一个有效 GPS 点。
2. 记录期间可切换页面。在「详情」可选择「10 秒自动熄屏」，闲置后显示纯黑层与 GPS 状态点，点按恢复。黑层期间应用继续在前台运行；实体按键真正熄屏或离开应用后的后台能力，需要在具体固件上验证。
3. 回到首页点击「结束」，等待保存完成，再点击「轨迹」查看文件列表。选择文件可查看轨迹点数、时长和海拔范围；列表未更新时点击「刷新」。
4. 删除单条轨迹：选择文件 →「删除文件」→「确认删除」。点击「取消」放弃删除，「返回列表」返回轨迹列表。

定位全程使用 `geolocation.subscribe`，经纬度、速度、海拔和精度均来自订阅回调。没有单次定位请求或定期重启定位。海拔显示一位小数；「详情」的「刷新定位」会更新订阅，不主动取消现有订阅或清零统计。GPX 每秒保存最近的有效定位，写入频率不代表硬件每秒产生新海拔；缺失的海拔不会补造。

记录期间，GPX 内会附带少量运行标记：转入后台、每分钟运行情况、定位错误、应用错误及结束方式。标记使用无换行的 XML 注释，每个约一百字节，不影响轨迹导入，不另外保存日志。点击轨迹可查看这些信息。若自动熄屏后退出，重新打开应用进入「轨迹」，等待未完成文件恢复，再查看该文件的「最后后台运行」、错误码和结束方式；也可以通过 AstroBox 导出 GPX 排查。没有销毁或错误标记不代表系统强制结束，退出时可能来不及完成写入。

GPX 包含经纬度、时间及设备返回的海拔，新录制及恢复生成的文件采用单行格式，不含回车或换行，以减少文件大小；已完成的旧文件保持原样。定位缺失或超过 5 秒未更新时跳过采样，海拔缺失时不写入该点的海拔字段。新文件名使用记录时的手表时区，列表时间按当前时区显示，GPX 内部时间使用 UTC。异常中断后进入轨迹页会尝试恢复未完成文件。

## 同步与导出到手机

1. 在 AstroBox 连接手表，保持手表上的速度计打开，在插件中选择设备并点击「同步手表列表」。只显示已经结束并保存的轨迹。
2. **单条导出**：点击轨迹上的「下载并导出」，完成后在系统弹窗选择保存位置。已下载文件可在「本地轨迹」点击「导出 GPX」。
3. **批量导出**：点击「下载全部轨迹」，完成后点击「全部导出为 ZIP」，选择手机上的保存位置，再用文件管理器解压到目标文件夹。ZIP 仅包含当前设备已下载完成的本地轨迹。

下载中断后可点击「继续下载并导出」续传。本地轨迹导出与删除不需要连接手表；「取消操作」停止后续处理，已完成的下载、导出或删除不会撤销。

## 删除与存储

| 插件操作 | 删除范围 | 保留的文件 |
| --- | --- | --- |
| 删除手表文件 | 选中的手表轨迹 | 本地副本和已导出文件 |
| 删除手表全部轨迹 | 确认列表中的全部已完成轨迹 | 正在记录的轨迹、本地副本和已导出文件 |
| 删除本地轨迹 | 选中的本地副本及下载进度 | 手表原文件和已导出文件 |
| 删除全部本地轨迹 | 当前设备的全部插件缓存，含未完成下载 | 其他设备缓存、手表原文件和已导出文件 |

所有删除操作都需要确认。手表轨迹保存在应用私有目录；卸载手表应用会清除其中的轨迹。本次测速统计与 GPX 文件删除无关。

## 常见问题

- **一直搜星／没有速度**：确认定位权限已允许，在开阔处等待；首次定位等待较久时保持订阅继续搜星，仅在订阅报错时自动重连。可在小米运动健康中同步设备以更新辅助定位数据；Vela 公开接口未提供手动更新 A-GPS 或指定搜星模式的参数。设备未开放 GPS 接口时无法使用，模拟器结果不能代替真机定位。
- **原生运动能定位，本应用一直搜星**：不能仅凭这一现象归因于冷启动或辅助定位数据。进入「详情」查看订阅状态、回调次数、海拔回传与变化次数、无效数据次数和接口错误码；搜星较久但回调为 0 表示尚未收到订阅数据，无效次数增加表示收到了本应用无法解析的数据。实时诊断保存在内存，只有记录中的少量运行标记附在 GPX 内。应用首次进入前台时订阅定位，持续订阅不因熄屏或静默等待而重启；[官方定位接口](https://iot.mi.com/vela/quickapp/zh/features/system/geolocation.html)没有提供切换原生运动搜星模式的参数。
- **真正熄屏后两三分钟退出**：退出原因尚未确认。目前自动熄屏改为前台纯黑覆盖层，以避开已观察到的自然熄屏退出路径；它不代表真实后台运行问题已修复。连续定位仍在应用级声明并订阅，后台普通订阅错误立即恢复一次，连续失败或权限问题延迟重试。系统终止应用后进入轨迹页可恢复 `.part` 文件并查看运行标记。参考[后台运行条件](https://iot.mi.com/vela/quickapp/zh/guide/framework/other/background-running.html)。
- **连接手机时原生运动搜星快，第三方慢**：[小米官方说明](https://www.mi.com/global/support/faq/details/KA-700622/)确认重新连接小米运动健康并同步可以改善 REDMI Watch 6 定位。手机辅助定位、星历同步或原生服务策略差异都可能参与；公开资料没有确认原生运动与 Vela 接口是否共享同一辅助通道。Vela 仅公开定位获取与订阅，没有读取星历有效期或注入辅助数据的接口，应用无法直接实现这部分系统能力。可以先同步小米运动健康，再在同一地点测试关闭蓝牙后的速度计，区分缓存辅助数据与持续手机协助。
- **海拔变化不明显**：小于一米的变化以前可能被整数显示隐藏，现已显示小数，海拔仅随订阅回调更新。如果「海拔回传」持续增加但「变化」不增加，说明接口仍在返回相同海拔。REDMI Watch 6 在[传感器支持明细](https://iot.mi.com/vela/quickapp/zh/features/system/sensor.html)中不支持气压接口，不能用第三方气压计绕过定位接口计算高度。
- **轨迹列表为空**：先结束记录并等待保存完成，再刷新列表或重新同步。
- **手表未应答／订阅权限失败**：检查 AstroBox 的设备连接和插件权限，重新打开手表速度计后同步；删除中断后重新同步，确认剩余文件。

## 开发

手表构建：`npm install` → `npm test` → `npm run build`。插件构建与权限说明见 [插件 README](speedometer-astrobox-plugin/README.md)，通信格式见 [GPX 同步协议](docs/astrobox-gpx-protocol.md)。根目录 [index.txt](index.txt) 指向插件构建产物，用于 [AstroBox 插件上架](https://abox.run/docs/creator-tools/resource-management/plugin-upload)。
